Project Intent

What is being developed?

Objective

Build a predictive machine learning model that reads safety reports written in normal English and predicts whether the report is a Mandatory Occurrence Report, also known as MOR.

Input Sources

The model uses two main sources: historical safety reports stored in Excel files and a structured MOR rules Excel created from the regulatory rulebook.

Expected Output

The system should return MOR or Non-MOR classification as of now. In future, we may expand it to display category, sub-category, confidence score, matched rule, and review requirement.

Preprocessing

What happens before model training?

01

Rulebook to Excel

The PDF rulebook is converted into structured rows containing rule ID, domain, category, sub-category, MOR condition, and keywords.

02

Report Text Cleaning

Raw reports are cleaned by removing extra spaces, special characters, email signatures, duplicate entries, and unnecessary identifiers.

03

Aviation Term Normalization

Abbreviations such as ACFT, RWY, TWY, APU, GPU, FOD, ATC are standardized for better model understanding.

04

Label Standardization

Labels such as Bird Hit, Birdstrike, Wildlife Strike are mapped into one standard class to avoid confusing the model.

05

Dataset Splitting

Cleaned reports are divided into training and testing sets, usually using a 70:30 or 80:20 ratio with stratified splitting.

06

Feature Preparation

Report text is converted into numerical form using TF-IDF or sentence embeddings before being passed into the ML model.

Testing & Evaluation

How the model will be tested

Accuracy

Measures the percentage of total correct predictions.

Recall

Important for MOR detection because missing an actual MOR can be safety-critical.

Precision

Measures how many predicted MOR cases were actually MOR.

F1-Score

Balances precision and recall into a single evaluation score.
